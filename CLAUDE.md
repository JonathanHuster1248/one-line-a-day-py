# Project Overview
A backend and frontend journal application that enables the addition of new journal entries and displays values by day of year so you can see previous year's journal entries for the same day. Entries can have up to 5 photo/PDF attachments. Entries and attachments are private per-user behind session-based authentication.

## Commands
- Dev frontend: `npm run dev` (run from `frontend/`)
- Build frontend: `npm run build` (run from `frontend/`; type-checks via `tsc --noEmit` before `vite build`)
- Typecheck frontend only: `npm run typecheck` (run from `frontend/`)
- Frontend tests: `npm run test` (Vitest + React Testing Library, run from `frontend/`); `npm run test:watch` for watch mode
- Dev backend: `.venv/bin/python -m one_line_day_py.main`
- Backend tests: `.venv/bin/pytest` (coverage via `pytest-cov`, see `.coverage`)
- Lint/format (backend): `ruff check --fix` / `ruff format`, wired up as pre-commit hooks (`.pre-commit-config.yaml`)
- Full stack via Docker: `docker compose up --build` — backend on `http://localhost:8000`, frontend on `http://localhost:3000`

## Structure

### Backend (`one_line_day_py/`)
Python 3.12+, using Litestar (API framework) + SQLModel/SQLAlchemy (ORM) + uvicorn + argon2 (password hashing) + Pillow/pillow-heif (attachment image processing).
- `main.py` — app factory (`make_app`) and uvicorn entrypoint. Registers `AuthController`, `RootController`, `JournalController`, `UserController`, `AttachmentController`. Builds the long-lived objects once into Litestar `State` (`users_db`, `journals_db`, `attachment_service`, `entry_attachments`) and exposes them to handlers via `Provide` dependencies of the same names; runs `attachment_service.sweep_orphans` `on_startup` (moves attachment directories whose entry no longer exists to `{attachments_path}/.trash/`, never deletes them). Wires up `SessionAuth` (Litestar session auth) with a server-side, file-backed session store (`FileStore`, stored alongside the DB in a `.sessions` dir), global `exception_handlers`, CORS from `settings` (no longer wide open), and logging (`create_logging_config`/`logging_middleware_config` from `src/logging_config.py`). `debug=settings.debug` (set `DEBUG=false` in prod to disable Litestar's debug tracebacks). `/schema`, `/favicon.ico`, and `/ping` are excluded from both session auth and access logging.
- `src/controllers/` — Litestar controllers, one per resource, re-exported via `__init__.py`:
  - `RootController` (`/`) — redirect to Swagger docs, favicon, and `/ping` (unauthenticated health check, returns `{"status": "ok"}`).
  - `AuthController` (`/auth`) — `signup`, `login`, `logout`, `me`. Signup/login/logout are excluded from auth; sets/clears the session cookie (`user_id`). Also exports `retrieve_user_handler`, used by `SessionAuth` to resolve `request.user` from the session on every authenticated request.
  - `UserController` (`/users`) — CRUD for users (list, get by id, get by name, update, delete). Update/delete enforce the caller can only modify their own record (`_check_is_self`, raises `PermissionDeniedException` otherwise). Delete removes the user, whose entries and attachment rows go via `ON DELETE CASCADE` (`UserDb.delete_user` returns the entry ids), then their files via `EntryAttachments.remove_entry_files`.
  - `JournalController` (`/journals`) — CRUD for journal entries, always scoped to `request.user.id` (no `author_id` query param anymore — entries are implicitly the caller's). `list_entries` supports optional `month`, `day`, `year` query filters (used to find same-day-across-years entries). Per-entry routes (`get`/`update`/`delete`) 404 if the entry isn't owned by the caller (`_get_owned_entry`).
  - `JournalController` also embeds each entry's attachment metadata in its responses (`JournalEntryPublic`, with `attachments` and `attachments_available`) through the narrow `EntryAttachments` protocol defined in `journal.py` (`for_entries`, `remove_entry_files`). `journal.py` and `JournalDb` import no attachment modules; `delete_entry` calls `remove_entry_files` after the delete commits (the rows go via `ON DELETE CASCADE`).
  - `AttachmentController` (`/journals/{entry_id}/attachments`) — `POST /` (multipart field must be named `file`; 16 MB per-request body limit), `GET /`, `GET /{id}/thumbnail` (320×320 WebP; `404` for PDFs), `GET /{id}/content` (display copy or the PDF; `?download=true` for an attachment disposition), `DELETE /{id}`. Calls only `AttachmentService`. Every route is scoped to the caller and the entry: another user's entry/attachment, or an attachment through the wrong `entry_id`, is `404`. File responses send `Cache-Control: private, max-age=31536000, immutable` and `X-Content-Type-Options: nosniff`.
- `src/dependencies.py` — `create_*`/`provide_*` functions for the `State`/`Provide` wiring above (`UserDb`/`JournalDb` from `settings.db_path`; `AttachmentService` from `settings.db_path` + `settings.attachments_path`), and `GuardedEntryAttachments`, the `EntryAttachments` adapter that never raises: a failed lookup logs the exception class and returns `available=False` so entries still load (`attachments_available: false`), and a failed file removal is logged and swallowed.
- `src/services/attachments.py` — `AttachmentService`, the one place for attachment rules: verifies entry ownership, enforces 15 MB (`MAX_FILE_BYTES`) and the type rule (JPEG/PNG/WebP/GIF/HEIC/HEIF images, or PDF with a `%PDF-` check), processes images off-thread, writes files then inserts the row (removing the files if the insert fails), deletes row then files, opens variants, and runs the orphan sweep (trash, not delete). Free of Litestar types. Logs only ids, kind, content type, size and error class — never filenames, bytes or EXIF.
- `src/images.py` — `process_image(data)`: decodes (HEIC via `pillow-heif`, first GIF frame), applies EXIF orientation, extracts `taken_at`, and produces a 320×320 cover-crop WebP thumbnail and a ≤2048 px WebP display copy (re-encoding drops EXIF). Raises `AttachmentProcessingError` on undecodable input.
- `src/data/attachment_storage.py` — `AttachmentStorage`: files at `{root}/{entry_id}/{attachment_id}.{variant}` (UUIDs only, never user input), written via temp file + rename; root created lazily, raising `StorageUnavailable` only on write. `trash_entry` moves an entry directory to `{root}/.trash/` (timestamp suffix on a name clash).
- `src/exceptions.py` — global exception handlers: SQLAlchemy's `NoResultFound` → `404`, plus the attachment domain exceptions `AttachmentLimitExceeded` (400), `AttachmentTooLarge` (413), `UnsupportedAttachmentType` (415), `AttachmentProcessingError` (422), `StorageUnavailable` (503), and `DuplicateEntryDate` (409, raised by `JournalDb` when an entry is created or moved onto a date the user already has).
- `src/logging_config.py` — `create_logging_config()` builds the Litestar `LoggingConfig` (console + a `RotatingFileHandler` writing to `.logs/app.log`, next to `.sessions`; level from `settings.log_level`); `logging_middleware_config` is the `LoggingMiddlewareConfig` for access logs, which deliberately logs only `path`/`method`/`status_code` — never request/response bodies, headers, or cookies, since those can carry passwords or private journal text. The `PIL`/`pillow_heif` loggers are pinned at `WARNING` because at `DEBUG` Pillow logs every EXIF tag it parses (camera, timestamps, GPS).
- `src/security.py` — `hash_password`/`verify_password` using argon2 (`argon2-cffi`).
- `src/schemas.py` — `SignupPayload`/`LoginPayload` request models, `to_public_user` mapper (strips `hashed_password` before returning a `User`), `JournalEntryPublic` + `to_public_entry` (entry plus `attachments`/`attachments_available`).
- `src/model.py` — SQLModel table definitions: `User` (now includes `hashed_password`), `UserPublic` (safe-to-return projection, no password), `JournalEntry` (unique on `author_id`+`date`; `author_id` FK `ondelete="CASCADE"`), `Attachment` (`entry_id` FK with `ondelete="CASCADE"`, denormalized `author_id` (also `ondelete="CASCADE"`), `kind` (`AttachmentKind`: image/pdf), `has_thumbnail`, `width`/`height`, `original_content_type`, `content_hash`, `taken_at`, `created_at`) and `AttachmentPublic`. The old placeholder `Photo` model was removed.
- `src/settings.py` — `CoreSettings` (pydantic-settings), loads `.env` via `python-dotenv`. Fields: `db_path` (default `one_line_day_py/src/data/journal_entries.db`), `debug` (default `True`; set `false` in prod to disable Litestar debug tracebacks), `session_cookie_secure` (set `true` in prod/HTTPS), `cors_allowed_origins`, `cors_allow_origin_regex` (defaults to permitting any `localhost`/`127.0.0.1` origin/port for local dev), `log_level` (default `"INFO"`, see logging setup in `main.py`), `attachments_path` (env `ATTACHMENTS_PATH`, default `one_line_day_py/src/data/attachments`; independent of `db_path`, only the defaults are siblings; relative paths resolve from the working directory).
- `src/data/db.py` — `UserDb` / `JournalDb` / `AttachmentDb`: the SQLAlchemy/SQLModel-backed data layer. `init_db` creates the DB file's parent directory if missing and turns on SQLite foreign keys (`PRAGMA foreign_keys=ON`) for every connection, which the cascades rely on. Schema comes only from `create_all` (no migrations), so it never alters an existing table. `AttachmentDb.add_attachment` checks the 5-per-entry cap (`MAX_ATTACHMENTS_PER_ENTRY`) and inserts in one session; lookups are always scoped by entry and author.
- `tests/test_src/` — pytest tests: `test_controllers/` (`test_auth.py`, `test_user.py`, `test_journal.py`, `test_root.py`, `test_attachment.py`, `test_journal_attachments.py`) plus unit tests beside them (`test_security.py`, `test_settings.py`, `test_db.py`, `test_attachment_db.py`, `test_attachment_storage.py`, `test_attachment_service.py`, `test_attachment_wiring.py`, `test_images.py`, `test_exceptions.py`, `test_schemas.py`, `test_logging_config.py`). `conftest.py` provides `app`/`client` fixtures (fresh app per test with `settings.db_path` and `settings.attachments_path` monkeypatched into `tmp_path`, so tests never touch the real DB or attachments directory) plus `alice`/`bob` sample signup payloads for multi-user auth tests.
- Swagger UI is available at `/schema/swagger/` when the server is running.

### Frontend (`frontend/`)
React 19 + TypeScript, built with Vite. Tested with Vitest + React Testing Library (`src/test/setup.ts` wires up `@testing-library/jest-dom` matchers and RTL cleanup); `*.test.ts`/`*.test.tsx` files sit next to the module they cover.
- `src/main.tsx` — mounts `<App />` (wrapped in `<AuthProvider>`) into `#root`.
- `src/App.tsx` — just the auth gate: renders `<AuthForms />` while logged out, otherwise `<JournalApp />`.
- `src/JournalApp.tsx` — the journal page: date picker with prev/next day and prev/next year navigation, loads/creates entries via `src/journals.ts`, lists same-day entries (`JournalBox` per entry) for the selected month/day, and surfaces load/create errors inline. The new-entry form includes an `AttachmentPicker`: on Send the entry is created first, then files upload sequentially (form disabled throughout); failures show in an `UploadFailureNotice` whose Retry targets the same entry. Logout button lives here.
- `src/JournalBox.tsx` — per-entry card component; view mode (with `AttachmentFooter`) plus inline edit/delete, with its own error surfacing on failed save/delete. Edit mode lists existing attachments with remove controls plus an `AttachmentPicker` (the 5 cap counts both); Save updates the text first, then deletes removed and uploads added attachments, reporting failures via `box-error`/`UploadFailureNotice` without undoing the text save. Reports attachment changes to the parent through `onAttachmentsChange`.
- Attachment components (each with a `*.test.tsx`):
  - `src/AttachmentThumb.tsx` — fixed-size tile: skeleton until the lazy thumbnail loads, in-place error with Retry; images are buttons (accessible name = filename) that open the viewer; PDFs link to their content in a new tab (icon + filename when `has_thumbnail` is false).
  - `src/AttachmentFooter.tsx` — the row of thumbs in a `JournalBox`, wrapped in an error boundary that falls back to "Attachments unavailable" (also shown when `attachments_available` is false). Owns the open `AttachmentViewer`.
  - `src/AttachmentViewer.tsx` — native `<dialog>` (`showModal()` on mount, `close()` on unmount; Esc's `cancel` → `onClose`) with the display image, Download link, and an in-dialog error if the image fails. jsdom lacks `showModal`/`close`, so tests stub them.
  - `src/AttachmentPicker.tsx` — controlled (`files`/`onChange`) file picker: visually hidden but focusable `<input type="file">` behind an "Attach files" label, drop zone, client-side count/size checks with inline messages, per-file remove and upload status, object-URL previews (revoked on removal/unmount) with a `FileIcon` fallback.
  - `src/UploadFailureNotice.tsx` — failed filenames + errors with Retry/Dismiss; shared by create and edit.
  - `src/FileIcon.tsx` — shared document icon.
- `src/attachments.ts` — API client for attachments: `uploadAttachment` (multipart `FormData`, no manual `Content-Type`; maps 400/404/413/415/422/503 to readable messages), `uploadAttachments` (sequential, never throws, returns `{ uploaded, failed }`, optional `onStatus` per-file callback), `deleteAttachment`, `thumbnailUrl`, `contentUrl`. Unlike `journals.ts`, the file goes in the body, intentionally.
- `src/date.ts` — pure date helpers used by `JournalApp`/`JournalBox` (`todayISODate`, `toISODate`, `formatMonthDay`, `formatYear`, `shiftDate`, `shiftYear`); covered by `src/date.test.ts`.
- `src/AuthContext.tsx` — React context (`AuthProvider`/`useAuth`) exposing `user`, `loading`, `login`, `signup`, `logout`; loads the current user on mount via `getCurrentUser`.
- `src/AuthForms.tsx` — combined login/signup form UI, toggles between modes.
- `src/auth.ts` — API client for `/auth/*` (`signup`, `login`, `logout`, `getCurrentUser`); all calls use `credentials: "include"` so the session cookie is sent/stored. `signup` throws `EmailTakenError` on the backend's 409, which `AuthForms` shows as-is.
- `src/config.ts` — `API_BASE_URL`, read from `VITE_API_BASE_URL` (falls back to `http://localhost:8000`); `MAX_ATTACHMENTS_PER_ENTRY` (5) and `MAX_ATTACHMENT_BYTES` (15 MB), hand-kept in sync with the backend constants (the backend enforces them; these only let the UI reject early).
- `src/journals.ts` — API client functions for journals (`getJournal`, `getJournals`, `createJournalEntry`, `updateJournalEntry`, `deleteJournalEntry`); create/update throw `DuplicateDateError` on the backend's 409 (an entry already exists for that date), which `JournalApp`/`JournalBox` show as-is; `createJournalEntry`/`updateJournalEntry` intentionally send `date`/`message` as query params (`URLSearchParams`), matching how `JournalController.create_entry`/`update_entry` bind those scalar args on the backend — not a bug, don't "fix" it to a JSON body.
- `src/models.ts` — the `Journal` type (incl. `attachments`, `attachments_available`) and `Attachment` type, imported wherever needed.
- No routing or state management library yet; state is local `useState`/`useEffect` in `JournalApp.tsx`/`AuthContext.tsx`.

### Cross-cutting notes
- No shared type generation between backend and frontend — the `Journal`/`Attachment` TS interfaces are hand-kept in sync with `JournalEntryPublic` (`schemas.py`) and `AttachmentPublic` (`model.py`).
- Frontend API base URL is configurable via `VITE_API_BASE_URL` (defaults to `localhost:8000`; set as a Docker build arg in `frontend/Dockerfile`/`docker-compose.yml`).
- Auth is server-side session based (Litestar `SessionAuth` + signed session cookie), not token-based. `SESSION_COOKIE_SECURE` should be `true` in production (HTTPS). CORS is restricted via `CORS_ALLOWED_ORIGINS`/`CORS_ALLOW_ORIGIN_REGEX` rather than wide open.
- `example.env` documents the env vars (`DB_PATH`, `ATTACHMENTS_PATH`, `DEBUG`, `LOG_LEVEL`, `SESSION_COOKIE_SECURE`, `CORS_ALLOWED_ORIGINS`, `CORS_ALLOW_ORIGIN_REGEX`, `HOST`, `ENABLE_DOCS`); `.env` is loaded automatically via `python-dotenv`.
- `backend.Dockerfile` (Ubuntu + `uv`, installs the package, runs via `uv run -m one_line_day_py.main`, exposes 8000) and `frontend/Dockerfile` (multi-stage Node build → nginx, exposes 80) exist for containerized runs; `docker-compose.yml` builds/runs both together and bind-mounts the SQLite DB file and the attachments directory into the backend container so they persist on the host (create `one_line_day_py/src/data/attachments` first, or Docker creates it owned by root; it's in `.dockerignore` so uploads aren't baked into the image). `frontend/nginx.conf` proxies `/api/` with `client_max_body_size 16m` (nginx's 1 MB default would reject photos).
